# Cherry Trace — Team 6 · підсумок хакатону

**Кейс:** General Cherry: Keep Shipping  
**Продукт:** внутрішній кабінет **Cherry Trace**  
**Напрями:** (1) зворотний звʼязок з поля → R&D · (2) якість і простежуваність на розподілених майданчиках  
**Звʼязок:** один серійник / партія — міст між цехом і полем

---

## 1. Проблема, яку ми вирішуємо

Коли в полі щось працює не так, R&D і контроль якості **не бачать швидко**, який саме серійник, партія чи майданчик — бо відгук і історія збірки живуть у чатах і таблицях окремо.

**Інформація рухається повільніше за виробництво.**  
Cherry Trace прискорює її одним ідентифікатором виробу.

Ми свідомо **не** чіпаємо: бойову частину, наведення, бойове застосування. Фокус — дані, логістика, якість, підтримка випуску.

## 2. Що зроблено (характеристики рішення)

### 2.1. Ролі та доступ

| Роль | Що бачить |
|------|-----------|
| **Розробник** | Повний кабінет: головна, трекінг, відгуки, якість |
| **Адмін Інженер R&D** | Логістика, карта трекінгу, відгуки, якість партій |
| **Збиральник** | Пункт збірки (Житомир / Одеса / Київ) → верстак |

- Демо-вхід з вибором ролі (sessionStorage)
- Навігація залежить від ролі
- Бренд GenCherry: темна палітра, accent `#ff3358`, JetBrains Mono

### 2.2. Головна (landing кабінету)

- Full-bleed hero з promo-медіа
- SplitFlap-заголовок: *«Інформація рухається / швидше за виробництво»*
- Scramble-ефект на CTA «Відкрити трекінг»
- CardSwap «Ми / Тримаємо / Темп»
- Картки статусів **Assembled / In Progress / In Transit** → перехід у трекінг із уже вибраним фільтром
- Crosshair-зона, reveal-анімації, нативний скрол

### 2.3. Трекінг збірки (напрям 2)

- Leaflet live-map (темна підложка Carto)
- **12+ фіктивних демо-зон** (не реальні адреси виробництв)
- **13+ дронів** у міні-БД з різними подіями збірки / QA / транзиту
- Фільтри **Assembled → In Progress → In Transit**: справа список дронів → клік відкриває маршрут (waypoints)
- Пошук за серійником / статусом
- Кнопка **«Якість партії»** з картки дрона

### 2.4. Якість партій (звʼязок 1 ↔ 2)

- Локалізація siblings за `batchId`
- Паспорт виробу: виробник, лінія, BOM / QA
- Таблиця **деталей виготовлення** (SKU, постачальник, лот, rev)
- Повторюваний сигнал з поля по партії

### 2.5. Відгуки з поля (напрям 1 у кабінеті)

- Donut / розбивка категорій проблем
- Стрічка звернень із лінками на партію / трекінг

### 2.6. Збиральник

- Вибір пункту: Житомир / Одеса / Київ (демо)
- Верстак: дрон, стан, комплектуючі, журнал (локально)

### 2.7. Адмін Інженер R&D

- Сторінка логістики переміщень
- Доступ до карти, відгуків і якості в межах своєї ролі

### 2.8. Польова PWA (окремо)

- `bootcamp/` — структурована форма, офлайн-черга, webhook (не прямий запис у БД)

### 2.9. Технічний стек (прототип)

| Шар | Рішення |
|-----|---------|
| UI | React 19 + Vite + React Router |
| Карта | Leaflet |
| Анімації | GSAP (SplitFlap, Scramble, CardSwap), OGL (GradientWaves на логіні) |
| Дані демо | `src/mocks/data.js` (синтетична міні-БД) |
| Auth демо | sessionStorage + рольові редіректи |
| Деплой | Docker / docker-compose (nginx для фронту) |

**Наступний етап (за рамками демо UI):** FastAPI, черга, ізольовані БД feedback / passport, HMAC, rate limit, IdP (Дельта / Дія).

## 3. Як це працює технічно (коротко)

```
Цех / верстак ──► паспорт (serial, партія, зона, BOM)
                         ▲
Поле (QR → PWA-форма) ──► відгук на той самий serial
                         │
                         ▼
              Кабінет: трекінг · відгуки · якість партії
```

1. **Один ID** зʼєднує збірку і поле — без пошуку в чатах.
2. **Ролі** обмежують поверхню UI: збиральник не бачить зайвого; інженер R&D працює з логістикою й партіями.
3. **Карта** показує лише фіктивні демо-зони + маршрути етапів (збірка → тест → логістика).
4. **Якість** піднімає паспорт виробника і BOM — щоб R&D бачив *з чого* зібрано виріб і *хто* в партії.
5. **Офлайн у полі** (PWA-черга) — збірка/звітність не зупиняються через даунтайм мережі.

## 6. Мініпітч

### Hook (проблема)

Keep Shipping — це не лише лінія збірки. Це ще й те, **чи доходить сигнал з поля до партії за хвилини, а не за дні в чаті.**  
Ми будуємо **Cherry Trace**: один серійник звʼязує верстак, маршрут збірки й структурований відгук — щоб R&D бачив партію, а не переписку.

### Що показуємо

- **Збиральник** за хвилини фіксує комплектуючі на пункті.  
- **Карта трекінгу** — Assembled / In Progress / In Transit і маршрут кожного виробу.  
- **Якість партії** — виробник, BOM, siblings, сигнал з поля.  
- **Інженер R&D** працює з логістикою й локалізацією в одному кабінеті.

### Технічна складова

Прототип — **React-кабінет** з рольовим доступом, Leaflet-картою, міні-БД маршрутів і паспортів, плюс **PWA-форма** з офлайн-чергою.  
Архітектурно форма не пише в БД напряму; далі — API з чергою, підписом і розділеними контурами feedback / passport. Без зайвих технологій заради технологій: QR + форма + паспорт + ролі.

### Безпека й периметр (мінімум захисту) — наша умова

Сайт **не виходитиме за межі корпоративної мережі** і буде доступний **лише в периметрі Адміна Інженера**, щоб трекінг і паспорти збірки **не потрапили далі** в відкритий інтернет.

Дистанційний доступ — **тільки через IPsec-тунель** з **налаштованою мультифакторною автентифікацією (MFA)**.  
Це наш **мінімальний базис захисту**: периметр + тунель + MFA, перш ніж нарощувати IdP, HMAC і сегментацію БД.

### Закриття

Інформація наздоганяє виробництво.  
Один серійник — один контур довіри всередині периметру.  
**Keep Shipping** — і тримаємо дані там, де їм місце.
